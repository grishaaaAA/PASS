# AUTODISP - нарядка без ручной работы

Сервис планирования выхода автобусов и водителей в наряды для ГУП «Пассажиравтотранс».

## Что уже есть

| Часть | Где | Что делает |
|---|---|---|
| Постоянная часть | `naryad/data/city.py` | Строит город по вводным: парки, маршруты, наряды, смены, автобусы, водители |
| Меняющаяся часть | `naryad/data/days.py` | День за днём: поломки и ТО, график 4 / 2, отпуска, больничные, медосмотр |
| Запуск и сводка | `naryad/data/generate.py` | Один день или серия дней подряд |
| Проверка данных | `naryad/data/check.py` | Ловит противоречия до того, как данные попадут в движок |
| CSV | `naryad/data/csvio.py` | Выгрузка в CSV и загрузка обратно в JSON |
| Настройки | `naryad/data/presets.py` | `case` - вводные заказчика, `park7` - парк №7 по справке на 12.05.2026 |
| Модель дня и плана | `naryad/core/model.py` | Читает день (после проверки данных) и план движка |
| Проверка плана | `naryad/core/invariants.py` | Ловит недопустимый план: автобус в двух местах, водитель без допуска, неисправный автобус на линии и т.д. |
| Нормы труда | `naryad/core/labor.json` | Нормы Приказа Минтранса № 160 (действует с 01.09.2026, заменил № 424) с номерами пунктов, статусом и пометкой, где проверяются |
| Наборы норм | `naryad/core/labor_presets.json` | Пока перевозчик не ответил: `current` (как в labor.json), `likely` (подготовка 20 + 10 мин, смены до 12 ч), `strict` (30 + 15 мин, норма 10 ч). Флаг `--labor` в `compare` и `series`, переменная `NARYAD_LABOR` для любой команды |
| Отдых водителей | `naryad/core/invariants.py`, `check_rest` | Отдых между сменами (11 ч / 9 ч, двойная смена) и еженедельный отдых (45 ч) на серии дней |
| Расстановка автобусов | `naryad/solve/vehicles.py` | Лучший возможный план по автобусам в принятой цене пропусков: при нехватке бережёт важные маршруты за счёт второстепенных, ставит свои автобусы на свои маршруты |
| Расстановка водителей | `naryad/solve/drivers.py` | Водители по сменам с памятью о прошлых днях: отдых по Приказу № 160, допуски, закреплённые автобусы, ровные часы |
| Серия дней | `naryad/solve/series.py` | `python -m naryad.solve.series --days 14` - автобусы и водители день за днём, сравнение с двумя моделями ручного способа |
| Пересчёт внутри дня | `naryad/ops/replan.py` | Сход, ДТП, неявка: до 3 вариантов замены с ценой за доли секунды; день описывается отрезками «с какого по какое время кто на наряде» |
| Сценарии дня | `naryad/ops/scenarios.py` | `python -m naryad.ops.scenarios` - 5 сценариев: сход, сход на 20 мин, ДТП, недопуск водителя, мороз (15 сходов) |
| Весь город | `naryad/solve/city.py` | `python -m naryad.solve.city --park P03 --share 0.25` - все парки, переброски лишних автобусов туда, где не хватает |
| Объяснения | `naryad/explain.py` | Почему этот автобус, этот водитель, почему наряд не закрыт, что даст вариант замены, сводка дня - текстом и цифрами для интерфейса |
| Ручной способ | `naryad/solve/baseline.py` | Аккуратные модели ручной расстановки (линия раньше резерва, свои автобусы, сверка отдыха со вчерашним нарядом) - точка отсчёта |
| Сравнение | `naryad/solve/compare.py` | `python -m naryad.solve.compare` - ручной способ против нашего: нехватка автобусов 5-20% (среднее и худший из 10 сценариев) и нехватка водителей 10-30% |
| Формат данных | `docs/CONTRACT.md` | Описание всех полей, включая формат плана, состояние дня после сходов и API движка (разделы «Состояние дня» и «API движка» - предложение, ждёт согласия Антона) |
| API движка | `naryad/web/api.py` | `python -m naryad.web.api` - http://localhost:8001: загрузить день, построить план (с перебросками между парками), объяснения, варианты замены на сход / ДТП / неявку, состояние дня отрезками, ручная правка плана диспетчером с проверкой норм, загрузка реестров перевозчика. Дни в памяти, ручки - в `docs/CONTRACT.md` |
| Показ заказчику | `naryad/demo.py` | `python -m naryad.demo` - готовый сценарий на одном парке через API: день, план, сход автобуса в 08:40, варианты с ценой, объяснение лучшего, план после замены, журнал. Данные из `data/samples`, интернет и генератор не нужны |
| Образцы ответов API | `data/samples/api_examples.json` | Реальные ответы по контракту API с дня парка №7, их пишет `python -m naryad.web.api --write-examples`, тест сверяет файл с живым кодом |
| Страница генератора | `naryad/web/` | Парки с вводными и результатом на день, выгрузка JSON / CSV |
| Страница без установки | `naryad/web/build_artifact.py` | Собирает одну страницу, которая работает в браузере без сервера |
| Образцы | `data/samples/` | Город по вводным кейса (1 день), парк №7 (будни и выходной, JSON и CSV) |

Нужен только Python 3.10+, сторонних библиотек нет.

## Страница генератора

**Без установки:** страница по ссылке в claude.ai (тот же интерфейс, генератор работает прямо в браузере). Пересобрать её после правок: `python -m naryad.web.build_artifact` -> `dist/autodisp_generator.html`. Логика страницы - `naryad/web/static/generator.js`, справочные данные она берёт из Python при сборке, а `tests/test_artifact.py` прогоняет её данные через ту же проверку на Python.

Номер набора на странице и в Python даёт разные данные: случайные числа у страницы свои (см. начало `generator.js`). Для показа заказчику цифры берём из Python, а не со страницы.

**Пока не публикуем.** Собранная страница содержит справочные данные парка №7 целиком (`build_artifact.py`, функция `data()`), а справка - внутренний документ перевозчика. До решения о том, что можно показывать, ссылку наружу не выкладываем. Там же два мелких дела: в собранном файле нет `<!DOCTYPE html>` и объявления кодировки, поэтому при открытии двойным кликом на русской Windows текст может читаться как каша, а счётчик «готово» на странице считает водителей с непройденным медосмотром, которых движок утром на линию не выпускает.

Запуск двойным кликом: **`start.bat`** на Windows, **`start.command`** на Mac. Файл подтянет свежую версию из GitHub, запустит сервер и сам откроет браузер. Окно сервера не закрывать, пока работаете со страницей.

Из командной строки: `python -m naryad.web.server` (адрес напечатается в окне; если порт 8000 занят, сервер возьмёт следующий свободный).

Сценарий диспетчера: пришёл утром, отметил парки, при необходимости поправил их вводные, нажал «Сгенерировать» и выгрузил данные на сегодня (JSON или CSV для Excel). Данные - на один рабочий день, от первого выезда до последнего возврата.

- В строке каждого парка - вводные (выпуск по классам, маршрутов, % исправных) и результат (исправны, наряды, водители, статус). Галочки и «Все» выбирают парки.
- У парка №7 можно взять цифры из справки на 12.05.2026.
- Клик по строке показывает, чего не хватает в этом парке.
- Сервер ничего не хранит: выгрузка заново строится по тем же вводным и номеру набора и совпадает с показанным.
- Страница помещается на экране без прокрутки от 1280×800 до 1920×1080.

## Запуск из командной строки

```
python -m naryad.data.generate                                   # 1 день по вводным кейса
python -m naryad.data.generate --days 30 --out series/           # 30 дней подряд
python -m naryad.data.generate --parks 3 --release 250 --routes 50 --mix 700,700,500
python -m naryad.data.generate --preset park7 --out park7.json --csv park7_csv
python -m naryad.web.server                                       # страница генератора, http://localhost:8000
python -m naryad.web.api                                         # API движка, http://localhost:8001
python -m naryad.data.registry data/samples/park7_weekday_csv --date 2026-10-05   # загрузка реестра
python -m naryad.demo --no-show                                  # показ: недопуск водителя и сход автобуса
python -m naryad.solve.series --days 14 --labor likely          # нормы из набора likely
NARYAD_LABOR=strict python -m naryad.ops.scenarios              # тот же набор для любой команды
python -m unittest
```

| Параметр | Что значит |
|---|---|
| `--date` | Первый день: суббота и воскресенье - выходные |
| `--days` | Сколько дней подряд; каждый день - файл `days/ГГГГ-ММ-ДД.json`, плюс сводка `series.csv` |
| `--seed` | Номер набора: одинаковый номер даёт одинаковые данные |
| `--moment` | `morning` - утро дня (медосмотр идёт), `plan` - план на завтра |
| `--parks`, `--release`, `--routes`, `--mix` | Вводные: число парков, выпуск парка, маршрутов всего, классы средний / большой / особо большой |
| `--readiness`, `--weekend` | Тех. готовность и выпуск выходного дня от будней |
