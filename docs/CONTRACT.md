# Формат данных, версия 0.2

Общий язык генератора, движка и интерфейса. Меняется только по согласию обоих (Григорий и Антон).

Набор данных - один JSON-файл. Движок читает только JSON. CSV загружается через `naryad.data.csvio.read_csv`, превращается в такой же набор и проходит ту же проверку.

```
{
  "meta":     {...},
  "parks":    [...],
  "routes":   [...],
  "duties":   [...],   наряды (выходы)
  "shifts":   [...],   смены внутри нарядов
  "vehicles": [...],
  "drivers":  [...]
}
```

Один файл - один день. Генератор выдаёт серию таких файлов подряд: постоянная часть (парки, маршруты, наряды, автобусы и водители как люди) в них одинаковая, меняется только состояние дня (исправность, график, медосмотр).

Время записывается как `ЧЧ:ММ` от начала суток. После полуночи часы идут дальше 24: `25:10` - это 01:10 следующего дня.

## Кто что заполняет

| Что | Кто |
|---|---|
| Исправен / неисправен, срок ремонта, график водителя, больничный, отпуск, медосмотр | Генератор (в жизни - парк) |
| Какой автобус и водитель на каком наряде | **Движок** |
| Группы «на маршруте / резерв / исправен в парке / неисправен» | Считаются из плана движка, показывает интерфейс |

Генератор никогда не ставит автобус на наряд: иначе движку нечего решать.

## meta

| Поле | Пример | Что это |
|---|---|---|
| format_version | `"0.1"` | Версия этого описания |
| preset | `"case"` / `"park7"` | Вводные кейса или реальный парк №7 |
| inputs | `{"park_count": 7, ...}` | Вводные, по которым построен город |
| seed | `1` | Номер набора: одинаковый номер даёт одинаковые данные |
| date | `"2026-10-05"` | Дата дня |
| day_index | `0` | Номер дня в серии, с нуля |
| day_type | `"weekday"` / `"weekend"` | Будни или выходной |
| moment | `"plan"` / `"morning"` | План на завтра (медосмотр ещё не проходили) или утро дня |
| source, assumptions | | Откуда цифры и что додумано |

## Проверка

`naryad.data.check.check(data)` возвращает `{"errors": [...], "warnings": [...]}`.

- **Ошибка** - данные противоречат сами себе (повтор номера, ссылка в никуда, смены не встык, список автобусов не сходится с `list_count`). Движку такие данные не отдаём.
- **Предупреждение** - данные целы, но расходятся с планом или не хватает автобусов либо водителей. Это рабочая ситуация, её и решает движок.

## План - ответ движка (версия 0.3, согласовано Григорием и Антоном 02.10.2026)

Отдельный JSON рядом с набором данных дня. Генератор его не создаёт, его выдаёт движок или правит диспетчер.

```
{
  "meta":                {"made_by": "engine", ...},
  "vehicle_assignments": [{"duty_id": "P07-R01-WD01", "vehicle_id": "P07-V0001"}, ...],
  "driver_assignments":  [{"shift_id": "P07-R01-WD01-S1", "driver_id": "P07-D0001"}, ...],
  "unfilled":            [{"id": "P07-R12-WD04", "reason": "no_vehicle"}, ...],
  "transfers":           [{"vehicle_id": "P01-V0123", "to_park": "P03"}, ...]
}
```

| Поле | Что это |
|---|---|
| vehicle_assignments | Какой автобус на каком наряде. Один наряд - не больше одного автобуса |
| driver_assignments | Какой водитель на какой смене. Водитель ставится только на смену наряда, у которого есть автобус |
| unfilled | Что осталось незакрытым и почему: id наряда (нет автобуса) или смены (нет водителя) |
| transfers | Переброски на день: автобус из одного парка работает на нарядах другого. Без записи здесь автобус чужого парка на наряде - нарушение |

Причины незакрытого (`reason`):

| Код | Что значит |
|---|---|
| no_vehicle | Нет исправного автобуса нужного класса |
| no_driver | Нет водителя с допуском, который работает в этот день |
| release_limit | Выпуск парка исчерпан |
| lower_priority | Ресурс отдан маршрутам важнее |
| park_down | Парк не выпускает автобусы |
| manual | Решение диспетчера |

Проверка плана: `naryad.core.invariants.check_plan(day, plan)` возвращает список нарушений. Пустой список - план можно выпускать. Незакрытый наряд с причиной - не нарушение, а честный план. Нормы труда для проверки лежат в `naryad/core/labor.json` вместе с источником и статусом каждой цифры.

## Объяснения для интерфейса (согласовано Григорием и Антоном 02.10.2026)

Модуль `naryad.explain`. Каждая функция возвращает словарь, который интерфейс показывает как есть:

```
{
  "question": "Почему наряд P07-R17-WD18 (маршрут 141) не закрыт?",
  "answer":   "Не хватило автобусов класса «большой»: исправны 196, все 196 заняты",
  "reasons":  ["Не вышли: 11 на ТО, 51 в ремонте", "Интервал в 11:32: по плану 7 мин, сейчас 8 мин", ...],
  "numbers":  {"vehicles_ok": 196, "vehicles_busy": 196, "planned_min": 7, "actual_min": 8, ...}
}
```

| Функция | Вопрос диспетчера |
|---|---|
| `why_vehicle(day, plan, duty_id)` | Почему на наряде этот автобус |
| `why_driver(day, plan, shift_id, history)` | Почему на смене этот водитель, и что с закреплёнными |
| `why_unfilled(day, plan, id)` | Почему наряд или смена не закрыты |
| `explain_option(state, event, options, i)` | Что даст вариант замены и чем он лучше следующего |
| `day_summary(day, plan)` | Сводка дня: что закрыто, где сосредоточены пустые наряды и смены |
| `interval(day, plan, route_id, t)` | Интервал на маршруте в момент t: по плану и фактический |

`answer` - одна фраза для карточки, `reasons` - пункты под ней, `numbers` - те же цифры для таблиц и графиков.
