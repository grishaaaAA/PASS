## 1. Порядок слияния - важно

`dispatcher-ui` сделана **от `api-contract`** (твоя ветка с API движка), потому что интерфейс работает через это API. Поэтому запрос на слияние `dispatcher-ui` → `main` сейчас содержит и все 18 коммитов `api-contract`.

Предлагаемый порядок:
1. Слить `api-contract` → `main`. Интерфейс построен на контракте API v0.1 **без изменений** - ни одной ручки не меняли и не добавляли в `api.py`; формально подтвердить согласие на контракт - Антону.
2. После этого в запросе `dispatcher-ui` останется только один коммит интерфейса - его и смотреть.

## 4. Как интерфейс собирает день для движка - проверь, пожалуйста

Диспетчер видит двоичные состояния, а в данные дня они переводятся так (`app/prep.js`, `buildDay`):

| Отметка | В данных дня |
|---|---|
| Маршрут выключен | его наряды и смены убираются; `release_<тип дня>` парка = оставшиеся наряды; `duties_<тип дня>` маршрута = 0 |
| Автобус «Неисправен» (был исправен) | `condition = "repair"`, `repair_days_left = 1` |
| Автобус «Исправен» (был неисправен) | `condition = "ok"`, `repair_days_left = null` |
| Водитель «Выходит» | `schedule = "work"`, `medical = "passed"` |
| Водитель «Не выходит» (был в графике и прошёл медосмотр) | `medical = "failed"`, график не меняется |

«Выходит» на экране = `schedule == work` и `medical == passed` (то же правило, что `may_depart` утром). Вопрос: не искажает ли такой перевод что-то в движке - например, память водителей между днями (`history_from`), если «не выходит» записан как непройденный медосмотр? Если лучше другой код (`day_off`, отдельная причина) - скажи, поменяем в одном месте.

## 5. Известные ограничения и риски

- **Python 3.9 у Антона:** `tests/test_api.py` не импортируется (`str | None` в аннотации на уровне модуля), остальные 209 тестов проходят. На 3.10+ всё зелёное. `naryad.web.server` (генератор) на 3.9 не стартует из-за проверки версии; `naryad.web.dispatcher` работает.
- **Несколько парков:** выбор нескольких парков и склейка их реестров в один день сделаны (переброски движок решает сам), но проверено только на одном доступном парке №7 - реестров других парков нет.
- **Публичный репозиторий:** в ветке фото ремонтной зоны парка №7 с сайта «Мойка78» (`app/img/park-P07.jpg`, проект учебный - так решил Антон) и трассы маршрутов. Справка парка №7 и так была в репозитории (см. предупреждение в `CLAUDE.md`).
- **Подложка карты:** бесплатные тайлы Esri - для показа заказчику и работы нужна своя подложка или договор.
- **Без входа по логину:** в журнале отметок пока IP компьютера, а не фамилия диспетчера.
