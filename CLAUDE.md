# PASS - контекст проекта для Claude

Сервис ежедневной нарядки автобусов и водителей для СПб ГУП «Пассажиравтотранс» (письмо Самойлова В.Ф., spbtrd.ru: адаптировать хакатонный проект dublikat; перевозчик обещал реальные реестры). Описание модулей - в `README.md`, формат данных - в `docs/CONTRACT.md` (разделы «План» и «Объяснения» согласованы с Антоном 02.10.2026, без согласия обоих формат не меняем).

- Только по-русски. Сначала вывод, потом объяснение. Чётко, структурно, без воды, таблицы и блоки.

## Ключевые факты и решения

- Нормы труда: Приказ Минтранса № 160 от 14.04.2026 (Минюст 15.05.2026 № 86476, действует с 01.09.2026), он отменил № 424. Все нормы - в `naryad/core/labor.json` с пунктами.
- Формула роста интервала (04.10.2026): цена пропуска считается как (нарядов по плану / остаётся работать) в кубе, пол - четверть автобуса при полной остановке. Раньше формула отставала на один шаг, и первый пропуск на маршруте из двух нарядов стоил столько же, сколько на маршруте из двадцати. Одна и та же формула теперь у утренней нарядки (`naryad/solve/vehicles.py`) и у пересчёта внутри дня (`naryad/ops/replan.py`).
- Правило утреннего медосмотра (04.10.2026): при `meta.moment = morning` на линию выпускается только водитель с отметкой `passed`; `pending` и пустая отметка - не допущен. В плане на завтра (`moment = plan`) `pending` это норма. Одна функция `naryad.core.invariants.may_depart` на весь движок. Цена правила: закрепление упало с 39% до 37%, зато разрыв с ручным способом по пустым сменам вырос.
- Ждём от перевозчика: длительность подготовки и медосмотров (`prep_before_min`, `prep_after_min`, сейчас 0), установлены ли смены до 12 ч (`city_12h_allowed`, сейчас null), учётный период, реальный порядок нарядки (стандарт «Планирование, подготовка и выпуск автобусов на линию»).
- Пока ответа нет: наборы норм в `naryad/core/labor_presets.json` (`current`, `likely`, `strict`), флаг `--labor` у `compare` и `series`, переменная `NARYAD_LABOR` для любой команды. Проверено 02.10.2026: подготовка 30 мин отдых 11 ч не ломает; при подготовке 45 мин без смен до 12 ч около 20 смен парка №7 в день длиннее нормы 10 ч - вопрос перевозчику, а не движку.
- Честные результаты (парк №7, пересчитано 04.10.2026 после правила медосмотра и исправления формулы роста интервала). Нехватка автобусов 15%: потеряно нарядов важных маршрутов 0,8 против 4,9 у ручного способа, часов на линии 86,9 против 92,4, худший рост интервала 1,2 против 1,44, маршрутов с ростом > 25% ноль против 1,9. Нехватка 20%: важных нарядов 10,3 против 15,6, часов 218,1 против 230, рост интервала 1,3 против 1,76, маршрутов с ростом > 25% 1,3 против 3,1. Водители за 2 недели: 0 нарушений у обоих, часы ровнее (44-65 ч против 35-73 ч), свой водитель на своём автобусе 37% против 38%. При 20% больных водителей пустых смен на важных маршрутах 0 против 46,8 в день, при 10% больных 0 против 2,2. Теперь по интервалам мы лучше ручного способа во всех клетках: прежнюю оговорку «интервалы не обещать» можно снять. Продавать: скорость, гарантия норм, ровные интервалы, пересчёт при сходах, объяснения.
- Известные ограничения: важность маршрута в генераторе по числу нарядов, а нужна по пассажиропотоку (Б2); 6 из 61 намеренных порч кода тесты не ловят (эвристики выбора, не законность).
- Показ заказчику: `python -m naryad.demo` (парк №7 из `data/samples` через API: план, сход в 08:40, три варианта, объяснения). Переброски между парками в API включаются сами, когда парков больше одного: на городе из 7 парков с ЧП в одном парке они спасают 44 наряда, план за 1,3 с. Внутри дня замена ищется только в своём парке - переброска это решение утренней нарядки.
- Данные справки парка №7 - внутренний документ перевозчика, наружу не публиковать.
